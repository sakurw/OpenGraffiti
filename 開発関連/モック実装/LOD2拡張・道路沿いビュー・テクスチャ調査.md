# LOD2拡張・道路沿いビュー・テクスチャ調査

更新日: 2026-09-08 / datasetVersion: `plateau-2025-v2`

## 対応結果

| 依頼 | 実装・結果 |
|---|---|
| テクスチャ付きLOD2にも描画 | 東京タワー側・都庁側とも対応。LOD2/3を画面・出典で区別 |

### 描画できる「任意の壁」の条件

- 選定した12面だけ、または道路から見える面だけ、という制限は撤廃。
- LOD2以上のWallSurfaceで、元ID・リングUV・テクスチャを追跡できる面。
- 非平面のWallSurfaceは同一平面部分へ分割。幅・高さ0.5m以上、面積0.5㎡以上の面を対象。
- 法線の鉛直成分0.35以下、ポリゴン平面誤差5cm以下。同一グループ内は法線と距離も検査。
- 屋根、テクスチャ未対応面、極小面、非平面として処理できない面は対象外。クリック時に案内。
- LOD2で写真に写った窓は穴としての形状を持たない場合があり、その領域も描画できる。存在する幾何学的な穴・壁外はマスクで除外。
- 長辺2048px、短辺は縦横比に合わせる。細長い実壁も選択できるよう、旧「短辺512px以上」の制限は撤廃。この設計差分は今回の任意壁対応に伴う仮決定。

## テクスチャ問題の切り分け

### 元データに由来する例を確認

確認壁: `d96e2da4-9d7d-5fca-a682-4024385fd2d8`（都庁周辺の壁4411、LOD2）。

- 建物: `bldg_40592bcd-88f3-4d4f-8e88-dfd8f3c2b89d`
- 元ポリゴン: `poly-0373a324-0de9-4858-a36d-3f03e1a84d8c`
- 配布画像: `WallSurfaceTexture_00008562_00008562_13104.jpg`
- [取得した元画像](../../public/assets/datasets/plateau-2025-v2/textures/source/7cc38af5ab3f62c75609461236049eeeb167223179795156ff98b50dafc5ae0c.jpg)
- 元UVの対象は画像左下側で、既に手前の建物・屋上設備が写っている。
- [描画画面の確認画像](画面キャプチャ/LOD2描画.png)

この例は「屋根のテクスチャファイルを誤って壁へ割り当てた」現象ではありません。対象メッシュの壁ポリゴン43,090件について、RoofSurface名の画像が壁に割り当てられた例は0件でした。ただしファイル名検査だけで画像内容の正しさを保証するものではありません。

31,542面すべての下地生成用UVは原本のUVと一致（V軸の座標系変換を除く数値誤差0）。非対称な四隅の色画像を使い、上下・左右の反転がない単体試験も追加しました。これは全壁の写真内容を人が検査したことや、GPUの完全な画素一致を保証する試験ではありません。

### 今回行った改善

- 元テクスチャとID/UVを維持し、アトラス化時に4pxの縁を複製。隣の画像をサンプリングする境界にじみを抑制。
- 航空写真に焼き込まれた陰影へ別の強い照明を二重に掛けない表示へ変更。
- 「均一材質で形状確認」を追加。見づらい写り込みを一時的に非表示にできる。編集下地・公開作品は変更しない。
- 選択した壁の下地は元画像から生成。街全体表示用の縮小画像を描画下地へ流用しない。

### どこまで解消できるか

| 原因 | 対処 | 今回 |
|---|---|---|
| UV反転・誤対応・隣画像のにじみ | 座標/ID対応の修正、余白、サンプラー設定 | 検証と対策を実施 |
| 航空写真に隣棟・屋根が写り込む | 遮蔽物のない別視点写真や地上撮影写真で面を再投影 | 元画像に隠れた壁の情報がないため自動復元は不可 |
| 元写真の低解像度 | より高精細な元写真・別年度データを比較 | 元画像のまま。架空の窓などは生成しない |
| LOD2形状が実壁形状と異なる | 対象建物をLOD3へ置換、またはモデル再計測 | データがある場合の次工程 |

見た目だけを埋める画像生成・インペイントは可能でも、実際の壁を復元したことにはならないため自動適用していません。追加写真を採用する場合は、利用権・撮影時点・壁ID・新datasetVersionを管理する必要があります。手動テクスチャ差替えUIは今回未実装です。

公式資料でも、[テクスチャは対応面に合わせた画像切り出しが推奨](https://www.mlit.go.jp/plateaudocument02/tocV/tocV_02/建築物モデルのテクスチャ作成における留意事項_/テクスチャのマージン_/)され、用途に応じた[壁面テクスチャの貼り替え](https://www.mlit.go.jp/plateau/learning/tpc26-2/)が紹介されています。

## 道路沿い2D表示の方式

1. 公式RoadのLOD1面の境界から主軸を推定。
2. 長さ25m以上、幅2m以上、長さ/幅2.5以上を対象にする。
3. 軸方向を6区間に分け、横方向の中心の揺れが `max(3m, 道路幅×0.35)` 以下なら「おおよそ直線」と判定。
4. 同一RoadのLOD3高さから道路基準高を近似。LOD1のz=0を地面高さとして使わない。
5. 道路軸から65m以内で道路側を向く壁を候補にし、道路上1.6mの視点から壁上3点へ線分判定。2点以上が建物で遮蔽されなければ採用。
6. 実道路軸への投影位置・横幅・基準高から、左側/右側の立面を配置。壁の並び順だけを作るカード表示ではない。
7. 指定時刻に対応する版を各壁で求め、同じ時点の道路景観を表示する。

地形の勾配、樹木、車両、道路歩道の厳密な観測点、立体交差などは完全再現していません。正式な道路中心線ではなくRoadポリゴンからの近似です。道路名はアプリ内識別名で、実際の通り名とは限りません。これらは仮決定・未検証事項です。

## 操作感度と負荷

Three.jsのパン量はカメラから注視点までの距離に依存します。[OrbitControls](https://threejs.org/docs/pages/OrbitControls.html)、[MapControls](https://threejs.org/docs/pages/MapControls.html)。

以前は注視点だけを境界に戻していたため、この距離が操作によって変化しました。更新後にカメラと注視点を同じ補正ベクトルで戻すことで、距離と向きを保ちます。ズーム位置追従、視点リセット、選択壁全体へ寄る操作も用意しました。

壁数増加への対策:

- 壁画像は選択・鑑賞時に遅延生成し、全31,542面を起動時に焼き込まない。
- 未公開の初期壁は元GLBのテクスチャを表示。描画オーバーレイは選択壁・公開作品だけに用意。
- 選択を外した未公開壁のGPUリソースを破棄し、選択するほど画像が溜まらないようにする。
- 元写真は街全体表示用に長辺最大512pxへ縮小し、2048pxアトラスへ集約。JPEG品質90・4:4:4、描画下地は元画像から生成。
- 画像キャッシュに上限を設け、公開されていない3万面の画像を2秒ごとに再取得しない。
- 定期通信は軽量な時計/変更番号API。変更がない場合は約29MBのカタログを再取得しない。
- 一覧は30面ずつ追加、画像は遅延読込。

GLBは東京タワー地区約29.9MB、都庁地区約40.5MB。PLATEAU VIEWと同じ広域タイル配信・距離別LOD切替・地形航空写真の表示は未実装です。2地区の対象メッシュを表示するローカルモックとしての拡張であり、PLATEAU VIEW相当の広域性能を達成したとは評価しません。

## 検証と保存

- TypeScript・production build: 成功。
- 単体12件: 退色/履歴、座標/穴/原本ID、反復パン、面クリック対応、道路形状/遮蔽、非対称UV。
- 生成fixture E2E 5件: 既存フローの回帰。
- 実データE2E 4件: LOD2/3の下地とマスク、都庁の実3Dクリック、連続パン、道路・日時、LOD2描画→プレビュー→公開→履歴→退色終点、バックアップ。
- 6,099ファイルのサイズ・SHA-256、31,542面すべてのGLBクリックID対応・元UV、195道路の参照整合を検証。
- 2048pxの画像生成/マスク全画素検査は代表6面。全31,542面の画像生成を網羅した試験ではない。
- [数値結果](検証データ/LOD2拡張検証.json)。GPU画像のMAE、長時間負荷、道路視認性の全件現地照合は未実施。

実装保存点: `1ae7153`。後続でメモリ解放・案内・検証文書を保存。

通常起動: `npm run build` → `npm start` → http://127.0.0.1:3100 （トークン `graffiti-demo`）。

データは `data/plateau-2025-v2/`。バックアップは実行状態・生成済み初期PNG・公開PNGとdatasetVersionを含みます。未生成の初期PNGは同梱v2のレシピと元画像から再生成するため、復元には `public/assets/datasets/plateau-2025-v2/` も必要です。旧v1データは保持。今回の途中生成アトラス125ファイルは `data/plateau/superseded-v2-atlases-20260908/` に退避して復元可能です。

## 確認していただきたい点

都庁の壁を3D画面からクリック→「この壁に描く」→公開、次に道路沿いビューで道を変更して左右の壁を確認してください。写真の写り込みに対しては、元の景観を保持するか、別途撮影した写真を採用するかが次の品質改善方針になります。今回は既存データを壊さず、元外観を保持する実装にしています。
