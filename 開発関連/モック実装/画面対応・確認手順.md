# 画面モック 対応表・確認手順

作成日: 2026-09-08 / 更新: LOD2対応v2

現行仕様と制約は [LOD2拡張・道路沿いビュー・テクスチャ調査](LOD2拡張・道路沿いビュー・テクスチャ調査.md) を参照。

## 起動

リポジトリルート `E:\OpenGraffiti` で実行します。

```powershell
npm ci
npm run setup:runtime
npm run build
npm start
```

`http://127.0.0.1:3100` をChromeまたはEdgeで開きます。開発用は `npm run dev`、URLは `http://127.0.0.1:5173` です。各画面のURLを直接開いても動作します。

`setup:runtime` はWindows x64向けNode.js 24.20.0を公式サイトから取得し、公式SHA-256と照合して `.tools/` に展開します。システムのNodeや実行ポリシーを変更しません。通常のbuild/start/dev/testは、このローカルNodeがあれば自動的に使用します。

既定の操作用トークンは **`graffiti-demo`**。右上「閲覧モード」から入力します。`OPEN_GRAFFITI_DEMO_TOKEN` 環境変数で変更できます。サーバーは127.0.0.1限定です。

## 画面と詳細設計

| 画面 | URL・入口 | 対応設計 | モックで操作できる内容 |
|---|---|---|---|
| 起動・共通ナビ | `/` | F-01・12 | 読込、エラー再試行、セッション、権限、独立URL、未公開編集の離脱確認 |
| 3D都市 | `/areas/tokyo-tower/city` | F-02・03 | GLB読込、左pan・右rotate・wheel zoom、作品貼付、クリック選択、壁検索 |
| 壁面詳細 | `/areas/tokyo-tower/city/walls/{wallId}` | F-04 | 現在作品、退色状態、版番号、描画開始、履歴、URL共有 |
| 下地確認 | `/walls/{wallId}/edit/source` | F-04・10 | サーバーで現在の退色状態を固定、再取得、2048pxキャンバス生成 |
| 描画 | `/walls/{wallId}/edit` | F-05 | 4ツール、色・サイズ・不透明度・硬さ・密度、10レイヤー、複製・削除・並替・表示、Undo/Redo各5回、拡大 |
| 3Dプレビュー | `/walls/{wallId}/edit/preview` | F-06 | 同じ統合PNGを壁へ一時投影、編集へ復帰 |
| 公開確認・完了 | `/walls/{wallId}/edit/publish` | F-06・07 | タイトル・表示名、トークン、PNG保存、次版追加、公開完了から街/履歴へ |
| 公開失敗・競合 | 公開操作から表示 | F-07 | 編集保持、再試行、旧/最新下地比較、差分表示、確認後の下地差替え、編集破棄 |
| 履歴 | `/walls/{wallId}/history` | F-08・10 | 版ごと、日時、タイムライン、前/次/現在、由来、区画同時刻への遷移 |
| 道路沿い2D | `/areas/{areaId}/sections/{roadId}` | F-09変更 | 195道路区間の位置図・選択、左右の実寸投影、同時刻表示、拡大、壁選択・描画・履歴・3D導線。旧tower-walk URLは地区の先頭道路へ |
| デモ時計 | 全画面下部 | F-11 | 再生・停止・先頭、履歴画面への導線、リセット確認・新scenario切替 |
| トークン入力 | 右上「閲覧モード」 | F-12 | 共有トークン入力、閲覧専用へ復帰 |
| 出典 | 右上情報アイコン | F-12 | モックと実データの区別、実データ出典、OSS表記 |
| 検証パネル | 下部右端の設定アイコン | F-01・07・12 | 起動/画像/3D/公開/競合の障害表示、保存データのバックアップ |
| 不明URL・壁なし | `/invalid` 等 | F-01 | 404画面と街への復帰 |

`{wallId}` は一覧で選んだ壁のUUIDです（例: `d96e2da4-9d7d-5fca-a682-4024385fd2d8`）。通常起動では31,542壁すべて0番目のみで始まります。壁に合うareaId（tokyo-tower / tocho）をURLへ指定してください。すべての壁に0番目があり、過去版から描く導線はありません。

## 一巡の確認

1. 3D都市で任意のテクスチャ付きLOD2/3壁をクリック。右の一覧は30件ずつ追加表示。地区選択で都庁にも切替可能。「選択した壁の全体へ」で壁に寄る。
2. 「この壁に描く」→下地確認→「この状態で描き始める」。
3. 描画・消去・レイヤー追加・Undo/Redoを試す。固定下地は変化しない。
4. 「3Dで確認」で上下・左右・大きさを確認する。「周辺を透過して壁を確認」をOFFにすると通常の建物遮蔽になる。
5. タイトル・表示名を入力し、トークン有効状態で公開する。
6. 履歴の連続番号、前作品、0番目、日時指定を確認する。
7. 道路沿いビューで道路位置図またはプルダウンを選択。道路から見える左右の壁・拡大・履歴日時を確認する。
8. 下部の退色再生を押す。15デモ秒で元の壁面に戻る。停止/先頭を確認する。
9. 「リセット」と入力して、新シナリオへ切り替える。

## データの保存と戻し

- `data/plateau-2025-v2/state.json`: 公開履歴、現在シナリオ、旧シナリオ、時計、冪等応答。
- `data/plateau-2025-v2/images/`: 壁面基底、サンプル、公開PNG。再起動後も保持。
- 旧生成モックの `data/state.json`・`data/images/` は変更せず保存。実データとは別領域。
- `data/plateau-v2-e2e/`: 実データ自動テスト専用。
- `data/e2e/`: 自動テスト専用データ。通常の `data/plateau-2025-v2/state.json` をテストでリセットしない。
- 公開前のレイヤーはブラウザの同一タブ内メモリに保持。タブを閉じると失われる。
- 検証パネルのバックアップは全シナリオ・生成済み初期PNG・公開PNG・datasetVersionを含むJSON。未生成初期PNGの再生成に同梱v2静的アセットが必要。旧v1データは data/plateau-2025-v1/ に保持。
- ファイル単位の復元は、サーバー停止中に別途退避した `data/` 一式を戻す。JSONだけを戻してPNGを欠損させないこと。
- Gitには実装・設計・生成GLBを保存し、実行データ・依存・ビルド出力は含めない。

## 自動検証

```powershell
npm test
npm run test:e2e
npm run test:plateau
npm run verify:plateau
```

E2Eはインストール済みChromeを使用。生成fixture試験は専用ポート3102、実データ試験は3103とそれぞれ専用データ領域で起動します。画面キャプチャは `test-results/`。実データ試験とUV往復検証を含みますが、BV全項目・本番性能検証を代替しません。モデルは同梱済みで再取得不要です。再生成コマンドの基本順序は [v1時点の変換手順](実データ適用・壁面抽出・実装評価.md)（現行スクリプトはv2を出力） を参照してください。

仮決定と本実装との差分は [仮決定・実装制約](仮決定・実装制約.md) を参照してください。
