# 四角い輪郭の実GUI検証と、接地を固定した地形の平滑化

2026-11-02。描画範囲と平滑地形について、同日以前の記録を更新する。

## 原因と修正

- 隠れた接続面を三角形単位で判定していたため、同じ面の別の三角形を端点と誤認した。部分的に見えている面の、隠れている部分も補完対象から落ちていた。同一平面の接続領域をまとめ、近傍で実際に見える両側の支持面を探す。描画範囲はその支持面の平面で挟み、画面外や開放端へは延ばさない。
- 小さなブラシでは支持面がブラシ円の外に出る場合がある。支持面を探す近傍だけを広げ、実際のインクは元の各粒子の形・サイズで切り抜く。密度・粒度・ソフト筆・消しゴムは維持。32px区画の範囲判定をカメラ姿勢ごとに再利用する。
- 都庁の実モデルで、閉じた四角から塗りつぶしが漏れる別の問題を再現した。探索用のUVマスクに付けた3pxの線が、詰めて配置された無関係なUV領域を接続していた。探索対象は正確な三角形の内側とし、UV境界の線形補間を隠す1pxの余白は探索終了後の結果にだけ付ける。面間の移動はモデルの接続辺を使う。
- 既存の作品を初めて合成するときは全体を初期化する修正を維持した。以後の描画は部分更新する。

## 実GUIの手順と証拠

既存の利用者データを混ぜない `http://127.0.0.1:3105` の検証用環境を使用。正式採用の都庁モデル `bldg_94caaf2f-dec2-41a7-8b0f-06ecd0fac6c7` を使用し、代替モデルには置き換えていない。

1. 編集画面でブラシを9pxに設定。実際のブラウザー操作で、画面座標 (790,530)→(860,530)→(860,680)→(790,680)→(790,530) の空いた四角を描いた。
2. 内側 (825,600) を別の色で塗りつぶした。修正前は四角の外側・建物上部まで色が広がった。
3. 元に戻し、輪郭を検証用作品「実GUI・四角い輪郭の検証」として保存。最新の処理を読み込み、同じ輪郭を開き直して同じ場所を塗りつぶした。内側だけが塗られ、外側の建物と以前のピンクの線は維持された。
4. Playwrightにも実モデルの同じ四角を追加。内側の複数点と、四角の外側の全画素の不変を検査する。カーソルの表示は色の検査から除外する。

## 地形の条件

建物・道路の原座標は動かさない。公式DEMは原本として残し、表示・歩行用の派生地形だけを生成する。

1. DEMから得た背景にメディアンと12mのガウス平滑化を適用。
2. 建物の元の底面三角形・辺を制約にした三角形分割を作る。底面の傾きも使用し、建物の外接矩形や最低高さだけに置き換えない。インデックス付きの形状にも対応する。
3. 建物外で背景地形へ連続的に接続する。制約を作った後に地形全体へ平滑化を掛けない。
4. 描画・歩行高さ・道路の色は同じ三角形面を使う。独立した道路面を浮かせない。

`scripts/test-pv-ground-contacts.mjs` は生成時の接地一覧を信用せず、`city.glb` から底面を再抽出して検査する。

| 検査 | 結果 |
|---|---:|
| 地上建物 | 126棟 |
| 接地点（頂点・辺・内部） | 12,690点 |
| 接地制約との最大誤差 | 約0.000343m |
| 接地を固定しなかった旧平滑化との最大ずれ（検査の対照） | 約9.424m |
| 内部の地面の亀裂 | 0 |
| 表示と歩行の頂点・索引の相違 | 0 |
| 平均凹凸指標（4m間隔の二階差分） | 0.3852 → 0.1184（約69%減） |
| 道路の地面欠落 | 184本・23,923点で0 |

元データにある例外も検査で区別する。

- `bldg_5da56097-5f78-481b-bcb6-a50a2d6aaad1` は元から高架の接続構造。地面を約14.4m持ち上げると下の空間を埋めるため、高架のまま維持する。地上126棟と合わせて採用127棟の全体を扱う。
- 元の隣接建物 `bldg_773000d3-5879-4899-b555-44b9037656c5` / `bldg_178c97c9-6d9b-4418-84ec-b6eb23f41490` の共有境界に約12cmの底面高の差がある。連続する単一の地面は同じ位置の両方の高さには一致できないため、元の低い側を保持する。この境界に由来する10点だけを原本から機械的に算出して区別し、それ以外を一律12cmまで許容する検査にはしていない。建物原本は変更していない。

報告：`public/assets/pv-adopted-20261029/walk-contact-audit.json`、`walk-smoothed-profile-audit.json`、`walk-smoothing-report.json`。

## 再実行

検証結果：TypeScript・Viteのビルド成功。Playwrightの全31件は2.9分で通過した。その後の支持面による平面クリップと範囲キャッシュの最終調整について、実モデルの四角、斜めの凹凸面、開放端、前面に隠れる面、裏面への過剰描画、筆設定・処理時間の対象6件を再実行し、全件通過した。最後の処理時間テストの通常描画バッチは2.1～10.7msで、100msの上限内。これは描画バッチの計測であり、全入力の遅延保証ではない。

道路側面の画像テストでは、地面の手前に別の建物が重なっている画素を、元モデルへの平行なレイで区別する。青い窓を「地面の欠落」と誤判定しないためで、地面自体の接地・亀裂・表示と歩行の一致は別途数値で検査する。
