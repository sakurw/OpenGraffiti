# 保存済みインクの実GUI再現と修正、局所描画範囲、平滑地形

2026-11-02。先の「描画表示安定・可視面限定・連続路面」より本書を優先する。

## 実GUIで確立した再現手順

実際に開いたEdgeのOpenGraffitiと正式採用の都庁モデルで、マウス操作によって確認した。普段の作品を変更しないため、同じアプリを3105番の隔離環境で起動した。

1. 都庁の描画画面で、ピンク色の水平線を描く。
2. 「街へ反映」で「インク表示 再現基準」として保存する。
3. 隠し操作画面でSpaceで退色を停止し、Homeで先頭へ戻す。
4. 「この建物に描画」で再編集し、保存したピンクの線が連続して表示されることを確認する。
5. 水色を選び、元の線から離れた下側へ最初の水平線を描く。

**修正前:** 元のピンクの線が縦の短冊状に部分的に消える。別の位置へ描くことが、既存インクの表示を欠損させる。同じ領域を更新すると表示が再び埋まる。

**修正後:** 手順1〜4で保存された同じ作品を開き直し、同じ位置・同じ色で手順5を実施しても、元のピンクの線が欠けずに残る。

実GUIの画像:

- 修正前: `test-results/ink-gui-before-fix.png`
- 修正後: `test-results/ink-gui-after-fix.png`

自動テストでも、単一の保存済みテクスチャに赤い点を置き、再編集して離れた位置へ青い点を置く条件を追加した。**修正前は失敗**（元の赤と青の画素差が期待値150超に対し -64）、**修正後は成功**。失敗のトレースは `test-results/ink-before-fix.trace.zip`、画像は `test-results/ink-regression-before-fix.png` に保存した。

## 原因と修正

`PaintDocument.compose()` が新しい出力キャンバスを作る際にも、ストロークの変更領域だけでクリップしていた。新しいキャンバスの外側には保持済みの画素が存在しないため、保存済み下地のその部分がコピーされず、GPU用の全体画像に透明部分が入っていた。保存済みの元画像そのものは残るため、後の更新や全体合成で復活する。

初回の合成では変更領域を解除して、保存済み下地とレイヤーを全体へ合成する。2回目以降は変更領域だけの処理を継続する。前回入れたGPUバインドの再設定だけでは、この初期化漏れは直らない。

## 描画範囲

従来は三角形の一部が見えるとその三角形全体を許可し、隠れた接続面にはブラシ全体で共通の最短・最長奥行きを使っていた。このため、部分的に隠れる部分や、片側が見えない端まで広がる場合があった。

- 可視面は、ブラシ内で前方の三角形に隠れる部分を奥行きと投影輪郭で切り取る。同じ三角形の一部だけが見えても、隠れた部分まで塗らない。
- 画面外の部分はビューポート境界で切り取る。
- 隠れた接続面は、投影した面を画面上の4px以下の区間へ分割する。各区間の両側に、隣接する可視平面が実際に存在するかレイで確認する。
- 両側が見える区間だけ、両側の実際の奥行きの間を補完する。片側が空白、画面外、別の無関係な面の場合は補完しない。建物裏側・外側の端へ伸ばさない。
- 粒度・密度・筆の種類は維持し、同じ粒子を許可された領域へ投影する。レイヤー、Undo/Redo、透過カラー、UV境界をまたぐ塗りつぶしも維持する。

回帰条件として「片端が開いた接続面の下半分には塗らず、両端が見える上半分だけ塗る」と「前景の面の後ろに隠れる三角形の部分には塗らない」を追加した。

## 平滑化した地形

公式の建物・地形ソースを保存し、表示と歩行用の派生地形を別ファイルで作成する。

- 公式DEMを4m格子でサンプリングし、3×3の中央値処理と標準偏差12mのガウス平滑化を適用した。
- `walk-terrain.glb` と `walk-surface.json` を生成する。表示と歩行判定の座標99,680頂点・198,090三角形を全要素照合し、位置・インデックスの不一致は0。
- 地面と道路は同じ平滑化後の連続面。道路材質が地面材質を覆うため、独立した道路面と地面の勝ち負けは発生しない。
- 平滑化は表示用の標高変更であり、現在表示する地形が公式DEMの全頂点と一致するという意味ではない。元地形からの標高変化は95パーセンタイル1.4113m、最大10.0044m。建物モデルの座標は変更していない。
- 格子の二階差分の平均は0.41186から0.04283へ約90%減少。全184道路の23,923サンプルで、隣接サンプル間の最大高低差は0.57545mから0.08733mへ減少。地形欠落0、歩行段差制限1.1mの超過0。
- 高架道路・橋の元メッシュを非表示とする、前回の地表路面方式は継続する。

生成: `scripts/build-pv-smooth-terrain.mjs`。元の `city.glb` / `terrain.glb` / `surface.json` は上書きしない。

監査: `scripts/audit-pv-road-profile.mjs --smoothed`。記録は `walk-smoothing-report.json`、`walk-smoothing-audit.json`、`walk-smoothed-profile-audit.json`。実GUI画像: `test-results/terrain-gui-smoothed.png`。

## 検証と配信

TypeScriptチェックとViteビルド成功。`tests/pv/revision.spec.ts` は **全29件成功（2.8分）**。保存済み下地、局所的な両端の可視性、前景による遮蔽の新規3テストを含む。レイヤー、Undo/Redo、公開・ギャラリー、退色、粒度密度、UV境界の塗りつぶし、歩行と建物衝突の既存26テストも成功した。既存の500kB超チャンクに関するビルド警告は残る。

ネイティブ建物の部分アップロード例は3.40ms・198,968画素。筆種別の最終バッチCPU処理例は丸筆1.3ms、点描1.3ms、粗粒スプレー0.7ms、ソフト消しゴム1.9ms。これらはテスト実行中の観測値で、全環境の上限値ではない。

通常の3100番サーバーへビルドと新規地形を反映。実GUIでも `data-surface-version=5` / `data-road-surface=roads-on-smoothed-dem` を確認した。ブラウザーの再読み込みで適用される。普段の保存作品は変更しない。比較用の3105番の実GUIには、保存したピンク線と追記した水色線が同時に残る状態を開いている。
