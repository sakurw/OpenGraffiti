# 道路の連続面・サイドバー再調整

2026-10-31。前の「PV追従改善・重ね表示・地面と衝突判定」より本書を優先します。

## 問題の原因と道路の修正

1. 前回は路面の輪郭頂点だけに高さを付けて大きな三角形を張り、別途6m格子の地面を作っていました。両者の内部高さが一致せず、道路が埋まったり、地面から浮いたりしました。polygonOffsetやrenderOrderだけで直る問題ではありません。
2. 重なった道路の最低面を地点ごとに選び、見つからない点だけ建物基部で補ったため、面の切り替わりで高さが飛びました。
3. 建物の部品メッシュ単位で最下点を基礎と見なし、上階の断片にも下へ延ばす面を作っていました。空中の補完面と衝突を生んでいました。
4. 道路選択のピンク表示には主軸に沿う長方形を使い、実際の輪郭・幅変化・曲がり・穴を失っていました。

現在は道路・地面を**単一の連続メッシュ**で表現します。既存の184道路ポリゴンを、穴を含む任意形状のカバレッジとして同じ面の材質へ合成します。171ポリゴンは頂点数が4を超える非長方形です。道路が独立した高さを持つことはありません。

表示順は明示的に **地面の色 → 道路ポリゴンの色 → 建物** です。最初の2つは1回の面描画の中で合成し、別の深度面を競合させません。建物と地面の位置関係は通常の深度判定を使います。

地面の高さは既存のネイティブ道路から2,498点を採り、平滑な4m格子の地表へ補完します。隣接三角形は頂点を共有します。歩行カメラは `src/pv-ground.ts` により、描画された三角形と同じ高さを直接計算し、別の道路や別レベルの高さへ突然切り替えません。急な補完斜面を抑え、道路内外を連続させています。

以前の別レベルの道路・橋の背景メッシュはPV画面で非表示にし、衝突対象からも除外します。元のcity.glbは変更しません。高架構造や地下道を確認・分類して接続する処理は行っておらず、この路面は地表としてつながるPV用簡略表現です。正確なDEMや立体交差の実測再現を主張しません。LOD1道路の輪郭データには高さ0しかないため、それだけを高さの根拠にしません。

基礎の補完は、部品の最下点ではなく建物全体の基部に近い実壁の底辺だけに限定。4m以下へ分割し、各底辺を共通地面の下へ接続します。地面との差が大きい高所には追加しません。上階断片の72,762辺を対象外にしました。正式採用した建物自体の形状・配置・テクスチャはそのままです。

## 地図・道路沿いビュー

選択表示とクリック判定も実際の道路リングで三角形化し、長方形の代理帯と帯の近くなら選べる判定を削除しました。曲線、多角形、穴を含む輪郭に対応します。

直線区間の経路は、主成分の平均軸ではなく、長い境界辺の方向と道路断面の中点から生成します。線分が輪郭外へ出る場合は区切り、連続する経路を採用します。選択対象の9区間は `scripts/pv-road-selection.json` に元道路IDとともに保存し、生成済みroads.jsonを次回生成の入力にしないようにしました。

道路沿いの固定正投影、左右切替、ウォークスルーへの移動は維持します。

## サイドバー・減退・レイヤー

- 620pxの2列サイドバーを右端・上下端へ接続。外側余白、角丸、浮遊する影、透ける背景を削除しました。complementary要素を維持し、背景を操作できる非モーダル表示です。220msスライドと、開閉で都市キャンバスを縮めない挙動は維持します。
- 減退はつまみやカーソル風マーカーを削除。細く角張った読み取り専用の帯で残り量を示し、塗り部分に透過グラデーションを持たせます。クリック・ドラッグ・キーボードの操作対象になりません。数値は可視表示せず、支援技術にはmeterの現在値を渡します。
- デザイン参照：[WAI Meter Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/meter/) の「範囲内の値の表示・キーボード操作なし」、[CarbonのProgress bar](https://v10.carbondesignsystem.com/components/progress-bar/usage/) のトラックと塗りの表示、[Androidの標準・モーダルDrawerの区別](https://developer.android.com/develop/ui/compose/components/drawer)。退色は処理進捗ではないため、ARIAはprogressbarではなくmeterです。見た目だけをCarbonの表示専用トラックから参考にしています。
- 「レイヤー 0 · 建物（固定）」の表示を削除。編集レイヤーの追加・複製・表示・並べ替え・Undoは維持します。

React部分は既存のreact-best-practices skillを参照し、頻繁に変わるゲージの更新をサイドバー内に留めています。

## 生成・監査

同梱Nodeで次の順に実行します。

```
node scripts/build-pv-terrain.mjs
node scripts/build-pv-roads.mjs
node scripts/audit-pv-surface.mjs
node scripts/runtime.mjs build
node scripts/runtime.mjs e2e --config playwright.pv.config.ts
```

出力は `public/assets/pv-adopted-20261029/terrain.glb`、`surface.json`、`surface-map.png`、`terrain-report.json`、`roads.json`。`src/pv-ground.ts` はカメラと生成・監査で共有します。

監査記録 `data/texture-city/pv-surface-audit-20261031.json`：

- 正式採用モデルのSHA-256を保持。
- 共有地表128,904三角形、内部の亀裂0、浮いた補完基礎の底0。
- 842点で描画面と歩行高さを照合。最大差0.00000381m。
- 道路材質の中点342点を画像から照合。
- 道路経路6,993点を元ポリゴン内に照合。約0.2mごとの高さ変化の最大値0.02515m。

実Chromeで都市・地図・歩行・端に接続したサイドバーを画像確認し、描画、レイヤー、最新作品保持、ギャラリー、正投影、歩行、衝突、サイドバーと読み取り専用メーターを検証します。画像は `test-results/road-before.png`、`road-walk-after.png`、`road-map-after.png`、`road-sidebar-after.png`。

最終検証：TypeScript・Vite成功、実Chrome E2E **9件合格（52.6秒）**。公開中の3100番ポートも更新済みのdistを配信します。
