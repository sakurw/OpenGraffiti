作成日: 2026-07-25  
最終更新日: 2026-08-31<br>
対象: 非エンジニア・企画担当・審査関係者向け  
ステータス: MVP要件確定  

詳細は[要件定義書](./要件定義書.md)を参照してください。

## 1. 一言でいうと

OpenGraffitiは、PLATEAUの3D都市モデルにある実在の建物壁面をデジタルキャンバスにし、ブラウザで描いたストリートアートを3Dの街へ反映できるコンテスト用デモです。

作品は上書きされても履歴に残ります。現在表示中の作品は時間とともに退色し、最後は単色の無地面ではなく、選択した建物壁面本来の見た目へ戻ります。

## 2. 利用者ができること

| 主機能 | できること |
|---|---|
| 街と壁を選ぶ | PLATEAUの3D都市を見て、描画対象として登録された壁を選ぶ |
| 現在の絵へ上書きする | 描画開始時の現在作品が退色していれば、その状態をそのまま固定キャンバスにして描き足す |
| 絵を描く | スプレー、ブラシ、マーカー、消しゴム、色、太さ、不透明度、レイヤーなどを使って描く |
| 3Dで確認する | 公開前に、描いた絵が壁へ正しい向き・大きさで表示されるか確認する |
| 作品を公開する | 描画を3D都市の選択壁面へ反映し、作者名・タイトル・履歴を保存する |
| 壁の歴史を見る | 何も描かれていない0番目から現在作品まで、上書きされてきた一本の履歴を見る |
| 過去の時点を見る | 履歴画面で過去の版を選ぶか、日時を指定し、その時点の壁または区画全体を見る |
| 退色を見る | 15秒のデモ表示で、鮮明→色あせ→輪郭のみ→元の壁面、という変化を見る |
| 3D都市で作品を見る | 作品が実際の3D壁面に貼り付けられた状態で街を鑑賞する |
| 区画の全壁を見る | 特定の通路・区画を選び、そこに並ぶすべての壁と現在作品を同じ画面で一度に鑑賞する |

## 3. 描画の大まかな流れ

1. すべての壁は、壁本来の見た目だけを持つ「0番目の作品」から始まります。
2. 3D都市から壁を選び、「この壁に描く」を選びます。
3. 描画開始時点の現在作品が、自動的に固定キャンバスになります。現在作品が退色していれば、退色した状態のまま引き継ぎます。
4. 過去作品を選ぶ操作はありません。必ず現在作品へ上書きするため、履歴は分岐せず一本につながります。
5. 固定キャンバスの上に絵を描きます。固定部分自体を消したり変更したりはできません。
6. 3Dプレビューで壁への反映結果を確認します。
7. タイトルと表示名を確認して公開します。
8. 公開した作品が現在作品になり、直前の作品は履歴に残ります。
9. 公開作品はデモ時間に沿って退色し、最後は選択した壁本来の見た目へ戻ります。

## 4. MVPの規模と前提

| 項目 | 内容 |
|---|---|
| 対象範囲 | 東京タワー周辺、港区2025年度のLOD3。道路2～3本程度の小規模な街区 |
| 描画壁面 | 基準12面。許容範囲10～20面 |
| 対象壁面 | PLATEAUのLOD3以上にある、単純でほぼ平らな壁。窓・扉は描画範囲から除く |
| 都庁周辺 | 新宿区2025の公式建築物はLOD2までのため、LOD3以上の正規データを確認できるまで描画対象にしない |
| 利用端末 | 13インチ以上のPCフルスクリーン、最小1280×720、最新版ChromeまたはEdge |
| 描画レイヤー | 固定下地とは別に最大10枚 |
| Undo/Redo | 各5回 |
| 壁ごとの履歴 | 0番目の作品1件＋ユーザー作品最大20件 |
| 退色デモ | 15秒で4段階 |
| 鑑賞モード | 3D都市ビューと、選択区画の全壁を一度に見る区画一括ビュー |
| 発表形態 | 実成果物を発表PCへローカル配置して使用する。事前収録を障害時の代替にする |

## 5. 今回実装しないもの

MVPでは、完成するデモを優先するため、次の機能は実装しません。

- スマートフォン向け描画と現地AR表示
- 描画を補助するAI機能
- 画像ファイルの取り込み
- アカウント登録・本人確認
- いいね、閲覧数、滞在時間による人気度計算
- 通報、モデレーション、権限・許可管理
- 決済、スポンサー、運用管理ポータル
- 建物解体後の3Dモデル保存

表示名は作品に保存します。作品を公開できる人は、デモ用の共有トークンで制限します。

## 6. 必要工数

### 6.1 工数の前提

以下は、実装コードがまだない現在の状態から、Codexを回数・トークン・実行時間の制限なく利用した場合に、**人が実際に作業・確認する時間**を人日で表したものです。1人日は8時間です。

Codexが実装、テスト作成、変換スクリプト、調査補助、修正、文書化を担当します。一方、対象エリアの決定、PLATEAUデータの確認、壁の見た目や向きの目視確認、操作性の判断、公開設定、最終受け入れは人が行います。

### 6.2 機能グループ別の概算

| 作業グループ | 最小 | 最頻 | 最大 | 主な内容 |
|---|---:|---:|---:|---|
| 要件最終確認・設計承認 | 0.5 | 1 | 1.5 | 確定した設計・API・データ形式の確認 |
| LOD3データ・壁面準備 | 8.5 | 14 | 23 | 港区2025 LOD3、opening、1壁面PoC、12壁の画像・向き・位置確認 |
| 3D都市表示・プレビュー・公開 | 6 | 9.5 | 15 | GLB表示、壁面選択、server検証、競合比較、作品反映 |
| 描画機能・画面の分かりやすさ | 4.5 | 7.5 | 11.5 | 現在作品への上書き、描画ツール、固定下地、レイヤー、操作導線 |
| 保存・サーバー処理 | 2 | 3 | 5 | SQLite、scenario、競合防止、冪等再送、エラー復旧 |
| 版/日時履歴・server退色・デモ操作 | 4.25 | 7.5 | 12 | 一本の履歴、日時指定、区画同時刻、15秒退色、原子reset |
| 区画一括・共有URL | 2 | 3 | 5 | 2モード切替、全壁配置、状態保持、共有導線 |

計画上の中心値は56人日です。三点見積もりによる期待値は57.9人日、期限検討用の丸め値は約58人日です。

### 6.3 人数別の期間目安

各担当者がCodexを無制限に利用し、週5日稼働する場合の目安です。

| 体制 | 期間の目安 | 最頻の目安 |
|---|---|---|
| 1名 | 約7～18週間 | 約11.2週間 |
| 2名 | 約4～12週間 | 約7週間 |
| 3名 | 約3～8週間 | 約5週間 |

人数を増やしても、同じPLATEAUデータの確認や統合作業があるため、単純に人数分だけ短くはなりません。

2026年9月1日から10月31日までは、土日と2026年の祝日・休日を除くと40稼働日です。推奨MVPの最頻56人日に16人日不足するため、週5日・一人で10月中に全量を確約できる見積もりではありません。10月末を守る場合は、1壁面PoC後に3～5壁面の最小ローカルデモへ絞る必要があります。推奨MVP全量の最頻完了は11月中旬です。

### 6.4 工数が増えやすい条件

- 対象壁面に元の色・模様を取得できるAppearanceやテクスチャがない
- 壁面IDやテクスチャの対応が変換時に失われる
- 曲面、穴のある壁、複数面にまたがる壁も描画対象にする
- 描画対象の壁を12面より増やす
- 認証、人気度計算、ARなど、MVP対象外の機能を追加する
- Codexによるファイル編集、コマンド実行、自動テストが制限される

## 7. 完成と判断する主な条件

- PLATEAU実データの街と描画対象壁面が表示される
- すべての壁が、壁本来の見た目と一致する0番目の作品を持つ
- 描画開始時の現在作品が、退色状態を保った固定キャンバスになる
- 過去作品から描画できず、0番目から現在までの履歴が一本につながる
- 3Dプレビューと公開後の見た目が一致する
- 新しい作品を公開しても以前の作品が履歴に残る
- 作品が退色した最後に、選択した壁本来の見た目へ戻る
- 3D都市で作品を鑑賞でき、区画一括ビューでは選択区画の全壁を一度に見られる
- 公開失敗や同時更新でも作品・履歴が壊れない
- 発表用の状態を1分以内に初期化できる

## 8. 決定状態と残る検証

対象、期限、体制、端末、技術、退色、履歴、発表方法は決定済みです。発表ではローカル実成果物を使います。未決の設計判断はありません。

残るのは、東京タワー周辺の実CityGMLから描画可能なLOD3壁面を12面確保できるか、2D/3Dの向きと外観が一致するか、退色・描画性能・12壁レイアウトが実機で合格するかという検証です。

実装では最初に1つの壁だけで「0番目の作品生成→現在状態を固定して上書き→3Dへの再反映」を試し、正しく表示できることを確認してから12壁面と区画一括ビューへ展開します。
