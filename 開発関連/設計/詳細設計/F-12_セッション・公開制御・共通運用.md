# F-12 セッション・公開制御・共通運用 詳細設計

作成日: 2026-08-22  
ステータス: 詳細設計ドラフト（未確定事項あり）

## 1. 目的

アカウント認証を持たないデモ利用者をブラウザ単位で識別し、表示名を作品へ保存します。閲覧と変更操作を分離する共有トークン、共通キャッシュ、ログ、障害回復、ライセンス表示およびローカル代替の論理インターフェースを定義します。

## 2. 対応要件

- FR-701～704、FR-801～803
- NFR-008、NFR-012～016
- AC-011、AC-018、AC-019

## 3. デモセッション

### 3.1 責務

- 初回アクセス時にブラウザ単位の`sessionId`を生成します。
- 表示名を公開確認時までに入力します。
- 初回公開時にDemoSessionを作成し、以後最終利用時刻を更新できます。
- Artworkへ公開時の表示名をスナップショット保存します。
- セッションを本人認証、権限、プロフィールとして扱いません。

### 3.2 DemoSession論理項目

| 項目 | 内容 |
|---|---|
| `sessionId` | 推測困難なブラウザ識別子 |
| `displayName` | 現在のデモ表示名 |
| `createdAt` | サーバー実UTC |
| `lastUsedAt` | サーバー実UTC |

ID生成、ブラウザ保存領域、寿命、破損・消失時の再発行はUD-023です。表示名規則はUD-017です。

## 4. 共有トークンによる公開制御

### 4.1 権限

| 操作 | 匿名 | sessionId | 共有トークン |
|---|---:|---:|---:|
| 3D・区画・履歴閲覧 | 可 | 不要 | 不要 |
| 描画エディタ利用 | 画面方針はUD-024 | 必要 | 公開時に必須 |
| 作品公開 | 不可 | 必須 | 必須 |
| 時計再生・停止・先頭化 | 不可 | 不要 | 必須 |
| デモリセット | 不可 | 不要 | 必須＋確認 |

### 4.2 サーバー検証

- クライアントの閲覧専用表示に依存せず、変更APIごとに検証します。
- 未設定、不一致、失効時は401相当で変更を拒否します。
- トークンをURL、画像メタデータ、ログへ含めません。
- 秘密情報をクライアントビルドへ固定埋込しません。

入力UI、保存、配布、更新、失効はUD-024です。

## 5. 共通入力セキュリティ

| 対象 | 検証 |
|---|---|
| ID | 型、長さ、許可形式、参照先存在 |
| 表示名・タイトル | 長さ、許可文字、Unicode正規化、HTML非解釈 |
| PNG | シグネチャ、デコード、寸法、容量、画素・マスク |
| 時刻 | ISO 8601 UTC、サーバー基準との整合 |
| 列挙値 | 定義済み値だけ |
| URL | サーバー・静的設定で管理した参照だけ |
| トークン | 定数時間比較等、採用基盤に適した方式 |

正確な型・長さ・PNG許可仕様はUD-015、UD-017、UD-043です。

## 6. レート制限・再試行

- 公開、時計変更、リセットへ最低限のレート制限を設けます。
- 読取APIの一時障害はページ全体を再読込せず再試行できます。
- 公開再送は同じidempotencyKeyを使います。
- 競合後に内容・下地を変えた再公開は新しいキーを使います。
- リセットは二重実行防止を行います。

上限、単位、タイムアウト、再試行回数、バックオフはUD-025です。

## 7. キャッシュ

| 対象 | 方針 |
|---|---|
| GLB、静的JSON、基底、マスク | 内容ハッシュ付きURL、長期キャッシュ |
| 公開Artwork画像 | 不変URL、長期キャッシュ |
| WallState、現在版 | 短期または再検証付き |
| DemoScenario | 短期、状態版または再検証付き |
| 退色生成物 | Artwork・基底・マスク・rendererVersion・progressの複合キー |

TTL、ETag、状態版、CDN構成はUD-003、UD-015、UD-044です。公開成功時は対象wallIdの動的状態とテクスチャだけを無効化します。

## 8. ログ設計

### 8.1 共通項目

| 項目 | 内容 |
|---|---|
| timestamp | サーバー実UTC |
| severity | INFO、WARN、ERROR等。確定値はUD-026 |
| eventCode | 機能別イベント |
| requestId | API要求の追跡 |
| appVersion | アプリ版 |
| datasetVersion | PLATEAUデータ版 |
| wallId等 | 必要な対象ID |
| result・duration | 結果、処理時間 |

### 8.2 必須イベント

- 公開成功・失敗・競合・冪等再送
- 画像読込・保存・ハッシュ検証失敗
- 退色生成失敗・rendererVersion未対応
- デモ時計変更・リセット
- 静的成果物の不一致
- WebGL重大障害

### 8.3 記録禁止・最小化

- 共有トークン、秘密鍵、DB接続情報
- PNG本体、描画座標列
- 不要な個人情報
- 表示名以外の本人情報

出力先、保持期間、閲覧・アラート、マスキングはUD-026です。

## 9. 画像ストレージ論理インターフェース

採用製品とローカル代替は、次の論理操作を同じ意味で提供します。

| 操作 | 内容 |
|---|---|
| `putCandidate` | 検証済み公開候補を不変キーで保存 |
| `exists` | ハッシュまたはキーで存在確認 |
| `getUrl` | 正式Artworkの取得URLを返す |
| `classifyOrphan` | DB未参照候補を削除候補に分類 |
| `deleteOrphan` | 再確認後に未参照候補だけ削除 |

物理API、キー、URL公開性、保持期限はUD-006、UD-014、UD-039です。

## 10. ローカル・リモート共通化

- 同じ静的成果物、設定スキーマ、初期データ、rendererVersionを使用します。
- 参照、公開、画像取得、時計、リセットの論理APIを揃えます。
- 同じ初期化シードで主要デモ結果を一致させます。
- ローカル代替で履歴・画像・整合性検証を省略しません。
- 実際に発表で使う配置はISSUE-001、ISSUE-002で決定します。

## 11. ライセンス・出典

成果物から次を確認できるようにします。

- PLATEAU対象都市、年度・版、出典
- 変換・前処理で使用したツール
- クライアント・サーバーの主要OSSとライセンス
- ライセンス本文または参照先

静的配信物または同梱文書へ含め、ローカル・リモートの両方で参照できるようにします。

## 12. 障害回復

| 障害 | 回復方針 |
|---|---|
| 読取API一時失敗 | 機能単位で再試行 |
| 作品画像取得失敗 | 壁面単位で再読込 |
| 画像保存成功・DB失敗 | 同じ冪等要求で候補画像を再利用 |
| DB成功・3D反映失敗 | 公開済みを維持し正式画像再読込 |
| 競合 | 編集保持、最新下地確認、再プレビュー |
| リセット失敗 | 直前利用可能状態を壊さず復旧 |
| WebGLコンテキスト喪失 | 再初期化し、未保存編集への影響を明示 |

## 13. テスト観点

- 初回にsessionIdを生成し、同じブラウザで再利用できる。
- 表示名変更後も過去Artworkの表示名が変わらない。
- トークンなしで閲覧でき、公開・時計変更・リセットはできない。
- 偽MIME、実体不正、容量超過、任意ファイルを拒否する。
- ログにトークン・画像本体・秘密情報が出ない。
- 公開失敗、画像失敗、競合をデモ中にログで確認できる。
- ローカルとリモートで同じシナリオ結果を得られる。
- PLATEAU出典・データ版・OSSライセンスを確認できる。
