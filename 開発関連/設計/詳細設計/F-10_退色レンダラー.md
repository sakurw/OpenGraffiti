# F-10 退色レンダラー 詳細設計

作成日: 2026-08-22  
ステータス: 詳細設計ドラフト（未確定事項あり）

## 1. 目的

公開済みArtworkを、同じ壁面の基底画像へ15秒で段階的に近づける決定的なRGBA画像生成を提供します。3D都市、区画一括、履歴、上書き下地確認、描画エディタ、3Dプレビューで同じ入力から同じ結果を得られることを保証します。

## 2. 対応要件

- FR-601～606、FR-216～218、FR-221、FR-222
- NFR-017、NFR-019
- AC-010、AC-015、AC-021、AC-022、AC-024、AC-027

## 3. 入力・出力

### 3.1 入力

| 記号・項目 | 内容 |
|---|---|
| `A` | 公開済みArtworkの自己完結RGBA画像 |
| `B` | 同じWallCanvasの壁面基底RGBA画像 |
| `M` | 同じ寸法の壁面マスク |
| `fadeStartAt` | 当該WallRevisionの退色開始デモ時刻 |
| `t` | 表示対象デモ時刻 |
| `rendererVersion` | 退色アルゴリズムとパラメータの版 |
| 参照情報 | wallId、Artwork画像ハッシュ、基底画像ハッシュ、データ版 |

### 3.2 出力

| 項目 | 内容 |
|---|---|
| `image` | M内不透明・M外透明のRGBA画像 |
| `progress` | `p`、0.0～1.0 |
| `stage` | 鮮明、色あせ、輪郭のみ、元の壁面 |
| `rendererVersion` | 実行した版 |
| `imageHash` | 規定の正規化方式による出力ハッシュ |

実行場所、画像ハッシュ、出力受渡し方法はUD-011、UD-013です。

## 4. 入力検証

処理前に次を検証します。

1. A、B、Mの幅・高さが一致する。
2. 幅・高さがWallCanvas設定と一致する。
3. AとBの画像ハッシュが参照メタデータと一致する。
4. Bのハッシュが`wallBaseImageHash`と一致する。
5. A、B、WallCanvasのPLATEAUデータ版が一致する。
6. Mが許可されたマスク形式である。
7. `rendererVersion`に対応する実装が利用可能である。
8. USER版では`fadeStartAt`と`t`が解釈可能である。

不一致時は画像を推測生成せずエラーを返し、上書き下地には使用しません。

## 5. 進行度・段階

USER版の進行度は次です。

```text
p = clamp((t - fadeStartAt) / 15 seconds, 0, 1)
clamp(x, 0, 1) = min(max(x, 0), 1)
```

| 条件 | 段階 |
|---|---|
| `0 <= p < 1/3` | 鮮明 |
| `1/3 <= p < 2/3` | 色あせ |
| `2/3 <= p < 1` | 輪郭のみ |
| `p = 1` | 元の壁面 |

時刻精度、浮動小数の丸め、境界比較の実装値はUD-012です。段階境界自体は変更しません。

## 6. 画像生成規則

### 6.1 確定規則

- `p = 0`では出力をAと画素単位で一致させます。
- `p = 1`では出力をBと画素単位で一致させます。
- 中間ではAとBの差分を作品成分として弱めます。
- 「輪郭のみ」では差分から抽出した輪郭だけをB上に残します。
- 元3D壁面をアルファ透過で露出させる方式を使いません。
- Mの内側は完全不透明、外側は完全透明です。
- Aの祖先Artworkを取得・再帰合成しません。

### 6.2 未確定の中間アルゴリズム

次はUD-012、UD-029の決定対象であり、現時点では式を固定しません。

- 鮮明・色あせ区間の補間・easing
- RGB、輝度、色差等の差分尺度
- 作品成分の差分閾値
- 輪郭抽出カーネル、線幅、色、不透明度
- sRGB・linear RGBの処理順
- アルファ、マスク境界、premultiplyの扱い
- 浮動小数精度、clamp、8bit量子化、丸め

## 7. revisionNo 0の処理

- 退色式を実行せずBをそのまま出力します。
- stageは「元の壁面」、progressは1.0として上書き下地の由来へ記録します。
- 0番目自体のWallRevisionでは`fadeStartAt = null`です。
- 0番目を上書きするUSER Artworkには全source項目が必要です。
- この場合の`sourceRendererVersion`と新RevisionのrendererVersionはUD-037で決定します。

## 8. 利用箇所別処理

| 利用箇所 | `t` | 出力の扱い |
|---|---|---|
| F-03 3D都市 | 共通の現在デモ時刻 | 現在オーバーレイ |
| F-04 描画開始 | APIが固定したsourceAsOf | 固定下地。以後更新しない |
| F-05 エディタ | F-04で生成済み | 固定下地としてのみ使用 |
| F-06 プレビュー | F-04で生成済み下地を焼き込んだ一時PNG | 一時PNG全体は再退色しない |
| F-08 履歴 | 選択版の表示期間内で選んだ時刻 | 過去状態表示 |
| F-09 区画一括 | 全壁共通の現在デモ時刻 | 全現在作品 |

新作品公開後は、固定下地と描画を焼き込んだ新Artwork全体を新しいAとし、公開時の`fadeStartAt`から`p = 0`で開始します。

## 9. 共通化と版管理

### 9.1 必須要件

- すべての表示箇所が同じ仕様とテストベクトルを使います。
- 公開済みRevisionが保持するrendererVersionで過去状態を再現できるようにします。
- rendererVersion変更後も、保存済み履歴が要求する旧版ロジックを利用できる必要があります。
- 未知のrendererVersionを別版で代替しません。

実装コードをクライアント・サーバーで共有するか、仕様とテストベクトルだけ共有するかはUD-011、UD-037です。

### 9.2 テストベクトル

各rendererVersionに次の固定fixtureを持たせます。

| fixture | 内容 |
|---|---|
| A | 色・線・透明境界を含む規定Artwork画像 |
| B | 同寸法の規定壁面基底画像 |
| M | 複雑でない非矩形マスク |
| p | 0、境界直前、1/3、1/2、2/3、境界直後、1 |
| expected | stage、規定RGBAハッシュ、端点画素 |

ハッシュの正規化とブラウザ間の一致判定はUD-013です。

## 10. キャッシュ

論理キャッシュキー:

```text
artworkImageHash
wallBaseImageHash
maskHash
rendererVersion
progressKey
```

- F-04の固定下地は正確なsourceAsOfとprogressに対応する結果を固定します。
- 表示アニメーション用のprogress量子化と、由来・ハッシュ検証用の正確なprogressを混同しません。
- progressKey、更新頻度、キャッシュ容量はUD-012、UD-020です。
- 入力画像またはrendererVersionが変わった場合は別キーです。

## 11. エラー

| コード例 | 条件 | 呼出元の扱い |
|---|---|---|
| `FADE_INPUT_DIMENSION_MISMATCH` | A、B、Mの寸法不一致 | 描画開始不可、表示エラー |
| `FADE_SOURCE_HASH_MISMATCH` | 入力画像ハッシュ不一致 | 再取得、代替不可 |
| `FADE_BASE_VERSION_MISMATCH` | 基底・データ版不一致 | 壁面描画不可 |
| `FADE_RENDERER_UNSUPPORTED` | rendererVersion未対応 | 当該版表示不可 |
| `FADE_RENDER_FAILED` | 画像生成失敗 | 機能単位で再試行 |

## 12. 性能

- 3D都市・区画一括の表示目標を妨げない処理時間とします。
- UIスレッドを長時間占有する場合はWorker、OffscreenCanvas、GPU等を検討しますが、採用方式はUD-011です。
- 12壁面同時更新、21版履歴選択、2048px長辺で計測します。
- 端点の画素一致と性能のためにアルゴリズムを別物にしません。

## 13. ログ

ログにはwallId、artworkId、入力ハッシュ、rendererVersion、progress、stage、処理時間、エラーコードを含めます。画像本体は記録しません。

## 14. テスト観点

- `p = 0`でAと画素一致する。
- `p = 1`でBと画素一致し、M外が透明である。
- 4段階の境界条件が規定どおりである。
- revisionNo 0は時刻に依存せずBになる。
- 同じ入力・版から全利用箇所で同じ規定ハッシュを得る。
- sourceAsOf固定後にデモ時計が進んでも固定下地が変わらない。
- 新公開作品全体がp=0から開始する。
- 未知rendererVersion、不正ハッシュ、異寸法を拒否する。
- Chrome、Edge、サーバー検証間の一致を確認する。
