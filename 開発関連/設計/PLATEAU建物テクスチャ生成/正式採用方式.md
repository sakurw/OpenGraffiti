# PLATEAU建物別イラストテクスチャ生成方式

正式採用日: 2026-10-29（ユーザーによる方式採用）<br>
対象: OpenGraffitiの建物外観生成・PLATEAUへの適用・出典監査・比較表示<br>
基準成果物: 都庁周辺12街区127棟、2026-10-19版

## 1. 採用する方式と適用範囲

**公式PLATEAUの形状・配置を保持し、建物の写真で確認できる部材・反復模様を分析してイラスト調の独自テクスチャを生成する。写真で確認できない面は、同一建物の観測済み部材から推測して補う。** 観測情報と推測情報は区別して記録する。

写真そのものの全面投影による写実再現ではなく、落ち着いた配色、細い線、簡略化された陰影による建築イラストを目指す。PLATEAU 2Dの次の画像をスタイルの参考とする。参考画像は対象建物の形状・窓配置の根拠にはしない。

- https://plateau2d.com/wp-content/uploads/2026/02/illust02-1536x652.png
- https://plateau2d.com/wp-content/uploads/2026/02/image-2-1536x859.png

正式採用はこの生成方式に対する決定であり、全127棟の写真根拠や全面の品質を認証するものではない。現在は建物別写真がない場合の手続き生成も含む。新しい建物のIDを表示対象に追加するだけでは、写真に基づくテクスチャ生成にはならない。

## 2. 現行の根拠と限界

以下は出典監査の分類である。今回の整理後にも監査を再実行し、679ファイルで欠落0・既存ハッシュ不一致0・その他の整合性指摘0を確認した。独自アトラス21画像の検証も通過した。写真の新規収集や過去の生成API呼び出しの再実行は含まない。

| 根拠・生成経路 | 棟数 |
|---|---:|
| 街路実写真からの生成 | 13 |
| PLATEAUの写真テクスチャ由来の模様生成 | 23 |
| 同一建物の追加写真を用いた推測 | 2 |
| 都庁第一本庁舎：写真・推測・手続き生成の混用 | 1 |

83棟にプロファイルがあり、残る44棟には個別写真による生成記録がない。写真のある建物でも内側・屋根・設備まで実測再現できたわけではなく、建物全面の写真カバレッジ認証は0棟である。SHA-256の一致はファイル同一性を確認するが、過去の生成AIが写真を実際に入力として使用したことを独立に証明しない。出典URL・著作者・ライセンスは記録情報であり、今回再判定したものではない。

## 3. 入出力と保持する情報

建物ごとにPLATEAU建物ID、街区、名称、写真のURL・ローカルパス・SHA-256・著作者・利用条件、写っている面や部材、遮蔽・解像度の限界を記録する。写真から切り出した領域、観測した特徴、推測した特徴、生成プロンプトと参照画像、生成結果と採用画像のハッシュ、加工内容、適用先マテリアル・タイルまで追跡可能にする。

最終的なデータの流れは次のとおり。

```text
対象街区・建物IDの確定
  → 同一建物の写真収集・部材分析
  → 建物別の正投影イラスト模様生成
  → 部材別調整・建物別プロファイル／外観供給用donor GLB
  → 公式PLATEAUのUVへ投影した独自アトラス
  → 原形状を用いる3D表示・出典監査・公式テクスチャとの比較
```

donor GLBは外観を供給する中間素材であり、最終表示の建物形状を置き換えない。

## 4. 生成・適用の手順

1. **対象を固定する。** 公式データの年度・配布元・ハッシュを保存する。道路で囲まれた街区を選定し、対象建物IDを確定する。現行は都庁周辺12街区127棟。道路・橋も公式形状を用いる。
2. **写真を特定する。** 位置、外形、名称等から同一建物を確認する。街路写真、公式写真由来の切出し、同一建物の別面を区別する。屋根だけが写る航空画像から壁の窓配置を観測済みとはしない。
3. **部材と反復を軽度分析する。** 主色、石・金属・ガラス、窓の形と縦横ピッチ、柱、帯、基壇、無窓壁、屋根、設備を分ける。観測と推測を別欄に残す。
4. **イラスト模様を生成する。** 対象建物の写真を内容の根拠とし、参考作品は描画スタイルに用いる。透視変形のない正面パターンとし、完全な窓単位・階の整数個で構成する。空・人物・道路・樹木・強い写真由来の影は混入させない。参照画像、プロンプト、ツールの結果、採用画像のハッシュを残す。画像生成は専用ツールで行い、既存画像の採用結果を保持する。過去と同一の画像が再生成されることは保証しない。
5. **部材別に加工する。** 壁・ガラス・屋根・設備を分け、建物内外の色調を揃える。写真不足面は同一建物で確認済みの模様を延長する。個別写真がない場合は汎用推測として表示・監査上で区別する。
6. **公式形状へ適用する。** 有限の共面壁群に整数個の窓モジュールを収め、壁端に余白・端部を設ける。屋根、設備、小面、無窓壁に窓を貼らない。意味属性を優先し、法線・高さ・面積による分類は推定として扱う。標高と楕円体高の違いを補正し、対応関係を記録する。
7. **独自UVアトラスを作る。** donor外観をBVH等で公式UVへ投影する。投影命中マスクを保存し、未命中を透明にして明示的な推測マテリアルへ渡す。独自表示用アトラスには元のPLATEAU写真画素を穴埋めとして残さない。
8. **重複・チラつきを防ぐ。** 3D TilesのREPLACE階層に従い、建物ごとの最細子孫と必要な兄弟断片を選ぶ。親子LODをADDとして同時表示しない。画像にはミップマップ・異方性フィルタ、反復シェーダーには画素フットプリントに応じたフィルタを用いる。
9. **実表示を確認する。** 全対象IDが描画されていること、端部・内側・設備、カメラ移動中の安定性を確認する。HTTP 200やビルド成功のみで完了としない。静止画の一致は移動中の安定性を保証しない。

## 6. 再検証と比較表示

PowerShellでリポジトリルートから実行する。既存の生成画を再生成せず検証できる。

```powershell
$tochoNode = '.tools/node-v24.20.0-win-x64/node.exe'
& $tochoNode scripts/audit-tocho-texture-provenance-20261019.mjs --strict
& $tochoNode scripts/build-tocho-own-only-atlases-20261018.mjs --verify
# 表示コードを変更した場合のみ再ビルド
& $tochoNode scripts/build-tocho-nine-blocks-viewer-20261018.mjs
```

比較画面はHTTPサーバーで `public/` を配信して開く。`file://` はGLB読込みのCORSエラーになる。独立した閲覧だけなら、Pythonが利用可能な環境で次を実行し、既存サーバーが同じポートを使っている場合はそのサーバーを利用する。

```powershell
python -m http.server 3110 --bind 127.0.0.1 --directory public
```

閲覧URL: http://127.0.0.1:3110/tocho-texture-comparison-20261019.html

左は独自パターン、右は元のPLATEAU写真テクスチャ。同じフィルタ済み形状とカメラを共有し、道路・橋の背景を揃える。照明モデルまで同一という意味ではない。独自側の元写真マテリアル数0と、公式側の写真マップ適用127棟を別に確認する。

保存済みブラウザ検証は `data/texture-city/tocho-texture-comparison-20261019/browser-verification.json` と同フォルダのスクリーンショット。両側127棟、建物タイル14件、共有カメラ、エラーなしを記録している。これは保存時点の検証であり、現在のブラウザ確認とは区別する。

## 7. 受入条件と変更時の管理

- 対象IDと表示IDが一致し、欠落・余計なLOD重複がない。
- 写真→加工／生成→採用画像→アトラス→表示先のリンクとハッシュが検査できる。
- 写真根拠の不足を、汎用生成や推測と区別する。推測を観測済みへ格上げしない。
- 壁端の不完全な窓、屋根・設備への窓誤適用、色の不連続、カメラ移動中のチラつきを実画面で確認する。
- 比較は全対象を同一形状・同一視点で表示する。変更時はスクリーンショットと件数・エラーを保存する。
- 方式採用を、全面実写真再現・PLATEAU 2D同等品質・全建物への無調整適用の保証に読み替えない。

## 8. 試行資料の保管とGit運用

今回の整理で不要になった試行スクリプト・旧レビュー資料・一時確認ファイルは、ローカルの `_local-backups/tocho-adoption-20261029/` に元の相対パスを保って退避する。`manifest.json` に元パス・サイズ・SHA-256・退避結果を記録し、同フォルダに復元用スクリプトを置く。正式資料は本書1件に集約し、退避物は正本として扱わない。

退避結果は2,227ファイル、547,416,767バイト。内訳は旧スクリプト1,009件、旧公開資料・画像等937件、ルート一時ファイル276件、過去の評価メモ5件。現行参照により保護した候補58件と、整理途中に対象外と判断した6件は元位置に保持した。全退避ファイルのハッシュ一致とGit除外を検証済みで、詳細はバックアップ内の `verification.json` に保存した。

現行表示、再生成、監査で参照する原写真・生成画・donor・アトラス・公式データは必要情報のため元位置に保持する。既に存在していたGit差分や削除は今回の整理と混同せず保持する。

`.gitignore` の `/_local-backups/` でバックアップ全体を除外し、Git追跡ファイルが混入していないことと `git check-ignore` を確認する。バックアップの強制追加（`git add -f`）は行わない。これは今後の通常の追加・コミット対象からの除外であり、過去のコミット履歴を消去する処理ではない。原写真等の継続利用する大きな現行資産は、今回の試行資料退避とは別の配布管理対象とする。

### ルート直下の整理

ルートにはREADME・ライセンス・アプリ入口と標準の開発設定を保持する。補助起動バッチ5件は `scripts/launchers/` に移し、実行時の作業ディレクトリ・相対参照をリポジトリルートへ補正した。各バッチの対象画面は従来どおりであり、旧実験用の起動経路も含む。

残存した一時コード・ログ・ビルド情報34件は同じバックアップフォルダ内の `root-cleanup/files/` に退避した。元パスとSHA-256は `root-cleanup/manifest.json`、復元手段は `root-cleanup/restore.py` に保存している。OCRの言語データは `.tools/ocr/tessdata/`、ローカルサーバー仕様ファイルは `.tools/tocho/server-spec.json` に配置し、いずれもGit対象外とする。通常のログ・検証出力は `data/` または `test-results/` に保存する。


## 2026-11-01追記：PV表示の地形と座標監査

PVの地面は同年度の公式CityGML `udx/dem/533945_dem_6697_op.gml` のTINを使用する。建物基部・道路から推測した補間地形へ置換しない。建物は公式B3DMからの再生成で採用GLBとバイト同一、地形は選択範囲内の65,796頂点・130,518三角形を原本と全数照合した。

CityGMLと採用3D Tilesの高さの関係は、この配布データに対する37mの差を全127棟で照合する。全国共通の標高換算値として扱わない。建物底面と地形の接触を強制せず、元データにある高低差も保持する。PVの道路着色は公式平面範囲をDEM上へ描く表示であり、LOD3高架・地下道路の全形状再現とは区別する。
