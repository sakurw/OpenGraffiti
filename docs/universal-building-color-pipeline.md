# PLATEAU普遍建物着色パイプライン

## ゴール

任意のPLATEAU建物に対して、公開写真を候補収集し、写真をそのまま全面へ貼らずに、建物固有の外壁色・階周期・窓ベイ周期を抽出して全壁面へ着色する。直接観測、同一建物からの推定、低根拠の設備色を区別し、各面にprovenanceとconfidenceを残す。

1棟PoCの合格条件は次のとおり。

- 左右の比較が同じPLATEAU全建物形状を使用する。
- 直接投影可能な写真は、カメラ登録・可視性・遮蔽・解像度ゲートを通過する。
- 写真の低周波照明と影を低減し、方向別atlasの代表色差をΔE76 10以下にする。
- 補正後も写真細部のエッジ相関0.82以上、輝度クリップ率1%以下を維持する。
- 未観測壁面は、同じ建物のappearance色を優先して補う。階・窓ベイ周期は、階別外周から2.25 m以内、幅4.5 m以上の外周壁に反復する。
- 形状規則で抑止された壁でも、held-out検証済み写真が同一WallSurfaceの25%以上かつ100 m²以上を直接観測している場合、その写真根拠を優先し、同じ面の未観測部だけへ周期を延長する。
- 写真根拠のない凹部、設備壁、塔屋、パラペット、短い壁には窓意匠を生成せず、画像根拠から安定化した単色を適用する。
- 別写真でパレットを検証し、未登録写真の画素をモデルへ投影しない。
- geometry-only、普遍着色、根拠品質、属性分類、補正済み観測合成、生投影を同じブラウザで切り替えられる。
- 面を選択すると、CityGML属性、形状subtype、色provenance、属性と色のconfidenceを表示する。
- HTTP配信、GLB読込、3D操作、左右カメラ同期、`file:`起動時のHTTPリダイレクトを自動検証する。

`根拠品質`表示では、直接観測範囲を緑、推定転写を黄、priorのみを赤で表示する。直接観測領域は基礎壁面と重なるため、全体面積の集計では二重加算しない。同一面内延長は`same-surface-observed-pattern-extension`として直接観測と分離し、GLB面の`sameSurfaceExtension`に直接観測面積、比率、延長面積、confidenceを保持する。

未観測部の補完優先順位は、同じ面の直接観測、同じ建物・同方向の観測pattern、PLATEAU appearanceの面色、同一設備群の色、属性priorの順とする。別の面から窓意匠を移すより、同一面に十分な直接観測がある場合を優先する。直接観測率25%未満、100 m²未満、幅4.5 m未満、またはカメラのheld-out検証不合格では面内延長しない。

## 形状から判別できる属性

CityGMLが明示している`WallSurface`、`RoofSurface`、`GroundSurface`、`OuterBuildingInstallation`は確定属性として扱える。高さ、法線、寸法に加え、各壁の中間高さで作る水平凸包からの内側量を測り、壁面をpodium/tower/recessed-service/crownへ細分化する。ただし、この細分類は形状仮説なので別の`subtypeConfidence`を持つ。

対象建物ではBuildingInstallationが2群あり、外形寸法は約9.33 × 2.41 × 12.91 mと29.21 × 12.55 × 22.28 mである。元CityGMLにclass/function/usageがないため、空調機、塔屋、目隠し壁などの具体名は確定できず、`roof-service-installation-unspecified`として保持する。

窓については、地上写真から階周期3.625–3.875 m、ベイ周期2.875–3.75 m、反復するglazing bandを検出できた。方向別の窓帯コントラストはΔE76 9.91 / 5.93、仮説confidenceは0.56 / 0.47である。元CityGMLのWindow polygonは0件なので、これは面の着色patternであり、個々の窓の位置・枚数・開閉方式を表す3D属性ではない。形状規則では26壁面中6面を適用対象とし、凹部・設備壁3面とパラペット・短壁17面を抑止する。今回、抑止対象の1面にheld-out検証済み写真が845.0 m²、面積の43.0%を直接観測していたため、写真根拠を優先して同じ面の未観測部へpatternを延長した。最終適用は7面である。観測9.6 m²、15.0%に留まる隣接短壁には延長していない。

設備は同じ`OuterBuildingInstallation`に属する面のappearance中央値を共有し、観測輝度を保ったまま彩度を72%低減して工業系中性色へ寄せる。これにより設備らしい差は残しつつ、屋根上で過度に目立つ色を避ける。具体的な空調機・塔屋・目隠し壁の名称は元データにないため確定しない。

## 処理

1. Commonsのカテゴリ、名称表記、住所、半径10 kmの位置検索とKartaViewの走行系列から候補を集める。
2. ライセンス、ハッシュ、重複、対象建物の同一性、昼夜、対象占有率を監査する。
3. 登録可能な写真だけをPLATEAU形状へ対応付け、可視性・遮蔽・有効画像領域・解像度で画素を選別する。
4. SNAP正射変換後、マスク対応Retinexと広域median照明推定で低周波陰影を低減する。
5. 方向別の輝度分位点とLab色を共同補正し、面境界をフェザーする。
6. CityGMLから面class、建物用途code、階数、BuildingInstallation所属を抽出する。
7. PLATEAU appearance画像4枚を181面のUVでサンプリングし、壁・屋根・設備ごとのrobust median paletteへ変換する。生の影・露出差・継ぎ目は転写しない。
8. 各壁の幅、高さ、階別凸包からの内側量を算出し、外周壁、凹部・設備壁、パラペットへ分類する。
9. 補正atlasの自己相関から階高3.625–3.875 m、窓ベイ2.875–3.75 mを検出し、外周条件を満たす6面を平滑なsemantic tileへ変換する。
10. 形状規則で抑止された各壁について、同一WallSurfaceの直接観測率・面積・幅とカメラ検証を評価し、閾値を満たす1面だけを面内延長する。
11. appearanceがない設備19面は同じBuildingInstallation群の色を転写し、設備色は観測輝度を保って低彩度化する。
12. 色根拠、属性根拠、形状subtype、窓帯適用可否を独立したconfidenceとして各GLB面へ記録する。
13. 根拠品質、属性分類、補正写真、生投影を監査用に残し、既定表示は継ぎ目のない普遍着色とする。

## 学習の要否

このPoCのCityGML面分類、色補正、appearance palette化、周期検出、信頼度管理には追加学習は不要。幾何、画像統計、自己相関、決定的な品質ゲートで再現できる。

多数建物で次の判定を自動化する段階では学習が有効になる。

- 写真内の対象建物instance segmentation
- 壁・窓・ドア・ルーバー・屋上設備のsemantic segmentation
- 昼夜、反射、樹木、車両、広告の除外
- 写真とPLATEAU輪郭・線分の初期対応
- 建物用途・年代・近隣統計からの材質prior

学習データには、PLATEAU面IDと写真maskの対応、材質クラス、観測可否、遮蔽mask、撮影条件、ライセンス、登録誤差を保存する。AI生成画像は観測証拠へ数えず、使用する場合も`generated` provenanceと0.3未満のconfidenceを別管理する。

## スケール方針

全候補にSfMや深層matchingを実行しない。GPS・方位・視線、建物同一性、昼夜、対象占有率で候補を先に落とし、1棟あたり登録候補を1–5枚へ絞る。登録済み写真は面単位で採点し、同一面の複数写真は露出補正後に中央値または信頼度重み付きで統合する。GPU処理は候補がゲートを通った建物へ限定し、候補探索・色統計・周期検出はCPUで行う。

## 再生成と検証

ローカルサーバーが起動済みの状態で次を実行する。

```powershell
powershell -ExecutionPolicy Bypass -File scripts\texture-snap-color-rebuild.ps1
```

比較ページ:

```text

```

実写真のカメラ初期登録には現在も少数の手動幾何制御がある。個別窓・ドア・設備機能を増やす次段階では、画像semantic segmentationとPLATEAU面への投影、複数視点一致、設備taxonomyの学習が必要になる。今回の成果は、候補収集後の色モデル化、CityGML属性利用、航空測量由来appearance色、陰影補正、全壁面補完、品質管理を普遍化した1棟PoCであり、存在しない属性を推測で確定値にはしていない。
